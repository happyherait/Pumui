# ADR 2. 구매요청을 Pull Request로 모델링한다

## 결정

구매요청을 변경 불가능한 리비전의 연속으로 저장하고, 승인을 리비전 해시에 묶습니다.

## 이유

기존 결재는 문서가 바뀌어도 승인이 남기 쉽습니다. Pull Request 모델은 이 문제에 이미 답이 있습니다. 새 커밋이 오면 이전 승인은 효력을 잃습니다.

## 결과

- 사양을 고치면 필요한 리뷰를 다시 받아야 합니다.
- 리뷰어 규칙을 코드와 분리된 텍스트 파일로 관리해 변경 이력을 Git에 남길 수 있습니다.
- 연구원에게는 낯선 용어이므로 화면에서는 품의서, 결재란 같은 익숙한 말을 씁니다.
