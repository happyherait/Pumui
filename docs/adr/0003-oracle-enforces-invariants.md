# ADR 3. 돈과 이력의 약속은 Oracle에서도 지킨다

## 결정

애플리케이션 검사 외에 행 잠금, 조건부 UPDATE, UNIQUE 제약, 트리거를 함께 사용합니다.

## 이유

동시 요청과 코드 결함은 애플리케이션 검사만으로 막기 어렵습니다.

## 결과

- 머지는 `SELECT ... FOR UPDATE` 안에서 최신 사실로 다시 판단합니다.
- 예산은 잔액 조건이 붙은 UPDATE로 차감합니다.
- 구매요청당 발주는 UNIQUE 제약으로 하나만 허용합니다.
- 리비전, 리뷰, 이벤트는 트리거로 수정과 삭제를 막습니다.
- 대신 PostgreSQL 등으로 옮길 때 SQL과 트리거를 다시 작성해야 합니다.
