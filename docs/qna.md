# 품의 Q&A

## 프로젝트

### 품의는 어떤 프로젝트인가요?

연구소 구매요청을 Pull Request처럼 다루는 시스템입니다. 요청마다 예산, 사양, 규제, 중복, 단가 체크가 돌고, 조건에 맞는 리뷰어가 자동으로 지정되며, 모두 끝나야 발주로 전환됩니다.

### 왜 이 주제를 골랐나요?

AI 프로젝트는 대부분 채팅창에서 끝납니다. 품의는 업무 절차를 바꾸는 데 AI를 씁니다. 연구원의 말을 구매 양식으로 옮기는 일은 AI가, 책임이 따르는 판단은 규칙과 사람이 맡습니다.

### 실제 서비스인가요?

아닙니다. 구직용 프로토타입입니다. 회사, 사용자, 품목, 단가, 규제 등급은 모두 가상이며 특정 회사의 시스템과 관련이 없습니다.

### 기술 스택은 무엇인가요?

React, Spring Boot, Oracle, Git입니다. AI는 Claude API를 사용합니다.

## 설계

### Pull Request와 무엇이 대응되나요?

요청은 Pull Request, 사양 리비전은 커밋, 체크는 CI, PROCUREMENTOWNERS는 CODEOWNERS, 발주 전환은 머지에 해당합니다. [ADR 2](adr/0002-purchase-request-as-pull-request.md)

### PROCUREMENTOWNERS는 무엇인가요?

리뷰어 지정 규칙을 담은 텍스트 파일입니다. 예를 들어 `hazard @EHS`는 규제 물질이면 안전환경 리뷰를 요구합니다. 규칙 변경도 Git으로 검토할 수 있습니다.

### 왜 규칙 엔진을 별도 모듈로 분리했나요?

스프링과 데이터베이스 없이 테스트하기 위해서입니다. 입력이 같으면 결과도 같은 순수 함수라서 규칙만 따로 검증할 수 있습니다.

### 공개 데모는 서버 없이 어떻게 동작하나요?

규칙 엔진을 TypeScript로도 구현해 브라우저에서 실행합니다. Java와 TypeScript 엔진은 같은 골든 케이스 파일로 검증합니다.

## AI와 보안

### AI는 무엇을 하나요?

자유 문장과 견적서에서 구매요청 초안을 만들고, 실패한 체크의 수정안을 제안합니다. 사람이 확인해야 저장되며 승인이나 발주 권한은 없습니다.

### 프롬프트 인젝션을 어떻게 막나요?

인젝션 자체를 완전히 막을 수는 없습니다. 대신 모델이 속아도 절차를 건너뛸 수 없게 했습니다. 견적서 원문은 모델을 거치지 않고 저장되고, 서버가 그 안의 CAS 번호를 규제 물질 표와 직접 대조합니다. [ADR 1](adr/0001-ai-proposes-rules-decide.md)

### 그럼 어떤 공격이 남아 있나요?

견적서에 CAS 번호가 아예 없고 품명만 있으며 품목도 마스터에 없으면 규제 물질을 자동으로 찾지 못합니다. 이때는 팀장 리뷰에 의존합니다. 실제 운영이라면 물질명 동의어 사전이 필요합니다.

### 승인 후 사양을 바꾸면 어떻게 되나요?

새 리비전의 해시가 달라지므로 이전 승인은 무효가 됩니다. 필요한 리뷰를 다시 받아야 발주할 수 있습니다.

### 동시에 발주를 누르면 어떻게 되나요?

구매요청 행 잠금으로 순서를 정하고, 예산은 잔액 조건이 붙은 UPDATE로 차감하며, 발주는 UNIQUE 제약으로 하나만 허용합니다. 8건 동시 머지 테스트로 확인합니다.

## 검증

### 무엇을 어떻게 검증했나요?

GitHub Actions에서 실제 Oracle Free 컨테이너로 통합 테스트를 실행합니다. 규칙 엔진 단위 테스트, 동시 머지, 예산 초과 방지, 트리거, HTTP 경로를 포함합니다. 공개 데모는 Playwright 시나리오로 확인했습니다.

### 실제 Claude 호출도 검증했나요?

자동 테스트는 가짜 Anthropic 서버로 요청 형식과 응답 처리만 확인합니다. 실제 모델의 초안 품질과 공격 대응은 아직 평가하지 않았습니다.

## 한계

### 실제 운영에 쓰려면 무엇이 더 필요한가요?

SSO, 공식 법령 데이터 연동, ERP와 공급사 연동, 입고와 검수 단계, 운영 모니터링이 필요합니다. 현재 사용자 식별은 데모용 헤더입니다.

### 규제 판단을 믿어도 되나요?

아닙니다. 등급과 대상은 시연용 가상 데이터이며 법적 판단이 아닙니다.
